# ISO 14229（UDS）常用诊断服务详解与报文示例

> 适用版本：ISO 14229-1:2020（第 3 版，业界主力版本）/ 中文采标版 GB/T 40822-2021
> 配套阅读：AUTOSAR CP SWS DiagnosticCommunicationManager（R24-11）
> 所有示例基于 CAN 总线（ISO 15765-2 传输层），字节均为十六进制

---

## 1. UDS 概述

统一诊断服务（Unified Diagnostic Services, UDS）定义于 ISO 14229 系列，是现代汽车 ECU 诊断的"通用语言"。它在 OSI 分层中的位置：

| 层 | 标准 | 说明 |
|---|---|---|
| 应用层（服务定义） | **ISO 14229-1** | 本文主角：SID、子功能、NRC |
| 会话层（时序） | ISO 14229-2 | P2 / S3 定时、会话状态机 |
| 传输层（CAN 实现） | ISO 15765-2（ISO-TP） | 单帧/多帧拆包组包 |
| AUTOSAR 实现 | Dcm / Dem 模块 | Dcm 跑协议，Dem 管故障 |

通信模型为 **客户端/服务器**：诊断仪（Tester）是 Client，ECU 是 Server，严格一问一答（Request → Response）。

**寻址方式（CAN 网络）：**

- **物理寻址**：请求 ID `0x7E0~0x7E7`（对应各 ECU），响应 ID = 请求 +8（如 `0x7E8`），点对点通信
- **功能寻址**：请求 ID `0x7DF`，广播给全车 ECU（典型用途：刷写前统一检查/关闭通信）

---

## 2. 报文通用格式与三条铁律

| 报文类型 | 格式 |
|---|---|
| 请求 Request | `SID(1B)` + `SubFunction(可选1B)` + 参数 |
| 正响应 Positive | `(SID+0x40)` + 回显参数 + 数据 |
| 负响应 Negative | `0x7F` + `SID` + `NRC(1B)` |

三条铁律：

1. **正响应 SID = 请求 SID + 0x40**。如 `0x22` 读数据 → 正响应 `0x62`；`0x31` 例程 → `0x71`。
2. **子功能字节最高位（bit7）是"抑制正响应位"**（0x80）。置 1 时即使成功也不回正响应，典型如刷写中周期发 `3E 80`。
3. **负响应统一为 `7F SID NRC`**。唯一例外：NRC=`0x78`（响应挂起）——ECU 表示"请求收到了，我还在算"，之后可连续发 `7F SID 78` 并不断重置 P2\* 定时器（刷写擦除 Flash 时动辄几秒，全靠它撑住），最终再回真实结果。

## 4. 各服务详解与报文示例

### 4.1 0x10 诊断会话控制 DiagnosticSessionControl

一切诊断的起点。不同会话解锁不同权限的服务：

| 子功能 | 会话 | 典型权限 |
|---|---|---|
| 0x01 | 默认会话 | 基础服务：22 / 19 / 14 / 3E 等 |
| 0x02 | 编程会话 | 刷写专用：34/36/37、内存读写 |
| 0x03 | 扩展会话 | 27 安全解锁、2E 写、2F IO 控制、31 例程 |

**报文格式**：正响应会回传两个时序参数 —— `50 子功能 P2(2B,单位ms) P2*(2B,单位10ms)`

```
诊断仪: 02 10 03                    ← 进入扩展会话
ECU:    06 50 03 00 32 01 F4        ← P2=0x0032=50ms；P2*=0x01F4×10ms=5000ms
```

**注意**：非默认会话下若 `S3` 定时（默认 5s）内收不到 `TesterPresent`，ECU 自动跌回默认会话，后续 2E/31 会突然报 NRC 0x7F/0x33——这是新手最常见的"玄学问题"。

---

### 4.2 0x11 ECU 复位 ECUReset

| 子功能 | 含义 |
|---|---|
| 0x01 | 硬复位（等效断电重启） |
| 0x02 | KeyOff/On 复位 |
| 0x03 | 软复位（仅复位应用层） |

```
诊断仪: 02 11 01        ← 硬复位
ECU:    02 51 01        ← 正响应后 ECU 复位（响应先于复位发出）
```

常见负响应：`7F 11 22`（条件不满足，如车速 ≠ 0 不允许复位）。

---

### 4.3 0x3E 诊断仪在线 TesterPresent

保持非默认会话不断开（喂狗），通常以 S3 周期的一半（约 2s）发送：

```
诊断仪: 02 3E 00        ← 需要正响应
ECU:    02 7E 00

诊断仪: 02 3E 80        ← 抑制正响应（刷写中最常用，总线干净）
（无响应）
```

---

### 4.4 0x27 安全访问 SecurityAccess

写敏感数据（0x2E/0x2F/0x31/0x34 等）前必须"对暗号"。机制：**奇数子功能请求种子 → ECU 回随机种子 → 按厂商私有算法算出密钥 → 偶数子功能发回密钥**。

```
诊断仪: 02 27 01                    ← 请求安全等级1的种子
ECU:    06 67 01 AB CD EF 01        ← 种子 = 0xABCDEF01

诊断仪: 06 27 02 12 34 56 78        ← 发送密钥（算法自定义）
ECU:    02 67 02                    ← 解锁成功
```

典型负响应（排错重点）：

| NRC | 含义 | 常见原因 |
|---|---|---|
| 0x24 | 请求顺序错误 | 没要种子直接发密钥 |
| 0x35 | 密钥错误 | 算法不对 / 种子-密钥不匹配 |
| 0x36 | 超过尝试次数 | 连错 3 次 |
| 0x37 | 延迟时间未到 | 失败后需等待（常见 10s）才能重试 |
| 0x33 | 安全访问被拒绝 | 没在扩展会话（未满足前置条件） |

---

### 4.5 0x28 通信控制 CommunicationControl

刷写前关闭应用报文，降低总线负载（报文不发出来，SDM 等其他节点也不会因丢帧报故障——配合 0x85 使用）：

| 子功能 | 含义 |
|---|---|
| 0x00 | 启用收发 |
| 0x01 | 启用收 / 禁止发 |
| 0x03 | 禁止收发 |

第二字节为通信类型：0x01 正常通信报文、0x02 网络管理报文、0x03 两者。

```
诊断仪: 03 28 03 03     ← 关闭正常通信+NM通信
ECU:    01 68

……刷写完成后恢复……
诊断仪: 03 28 00 03     ← 恢复
ECU:    01 68
```

---

### 4.6 0x22 读数据 ReadDataByIdentifier（最高频服务）

按 **DID（2 字节数据标识符）** 读取，一个请求可带多个 DID。

```
诊断仪: 03 22 FD 01                 ← 读 DID 0xFD01（示例：当前车速）
ECU:    04 62 FD 01 64              ← 0x64 = 100（单位 km/h，编码自定义）
```

常见标准 DID（F1xx 段为 ISO 定义）：

| DID | 含义 |
|---|---|
| 0xF190 | VIN 车架号（17 字节 ASCII） |
| 0xF191~0xF199 | 备件号 / 软件、硬件版本号系列 |
| 0xFD00+ | 厂商自定义段（车速、电压、温度等） |

负响应：`0x31` DID 不支持、`0x33` 需安全解锁、`0x22` 条件不满足。

> 含多帧的完整 VIN 读取示例见第 5 节。

---

### 4.7 0x2E 写数据 WriteDataByIdentifier

与 0x22 对应，通常要求：扩展会话 + 0x27 安全解锁，且 DID 必须支持写入。

```
诊断仪: 04 2E 12 34 AA              ← 向 DID 0x1234 写入 0xAA（如标定参数）
ECU:    02 6E 12 34
```

产线上写 VIN 也是它：`10 14 2E F1 90 ...`（VIN 较长，走多帧）。

---

### 4.8 0x23 / 0x3D 按地址读写内存

刷写配套、对标定/调试用途，直接操作物理地址。第二字节 **地址长度格式标识符 ALFID**：高半字节 = 长度字段的字节数，低半字节 = 地址字段的字节数。

```
诊断仪: 07 23 14 00 00 10 00 04     ← ALFID=0x14：地址4字节、长度1字节
                                     ← 读地址 0x00001000 起 4 字节
ECU:    05 63 AB CD EF 01           ← 回 4 字节数据
```

写内存 `0x3D` 格式同理（`3D ALFID 地址 长度 数据` → 正响应 `0x7D`）。

---

### 4.9 0x2F 输入/输出控制 InputOutputControlByIdentifier

诊断仪"接管"执行器（产线 EOL 测试、维修动作测试）：

| 控制参数 IOCP | 含义 |
|---|---|
| 0x00 | 控制权归还 ECU |
| 0x01 | 复位为默认值 |
| 0x02 | 冻结当前状态 |
| 0x03 | 短期调整（附控制值） |

```
诊断仪: 05 2F F0 01 03 64           ← DID 0xF001（示例：测试电机）短期调整到 0x64=100%
ECU:    05 6F F0 01 03 64
```

**安全提醒**：IO 控制会真实驱动执行器，通常有车速 = 0 等前置条件（不满足回 NRC 0x22），做完务必归还控制权。

---

### 4.10 0x31 例程控制 RoutineControl

"执行一段 ECU 内置程序"的通用入口：自检、擦除 Flash、恢复出厂、清学习值都走它。**RID（2 字节例程 ID）**：`0xFF00` 擦除内存、`0xFF01` 编程完整性检查为标准定义，其余厂商自定义。

| 子功能 | 含义 |
|---|---|
| 0x01 | 启动例程 |
| 0x02 | 停止例程 |
| 0x03 | 请求例程结果 |

```
诊断仪: 04 31 01 FF 00              ← 启动擦除内存例程（可附地址/长度参数）
ECU:    04 71 01 FF 00              ← 例程已启动（长操作后续可回 78 挂起帧）

诊断仪: 04 31 03 FF 00              ← 查询例程结果
ECU:    06 71 03 FF 00 01 00        ← 状态记录：0x0100 = 成功（示例）
```

常见 NRC：`0x31` RID 不支持、`0x33` 未解锁、`0x72` 例程执行失败、`0x24` 例程正在运行。

---

### 4.11 0x19 读故障码 ReadDTCInformation

| 子功能 | 含义 |
|---|---|
| 0x01 | 按状态掩码查 DTC **数量** |
| 0x02 | 按状态掩码列出 DTC **明细** |
| 0x04 | 读某 DTC 的**快照**（冻结帧） |
| 0x06 | 读某 DTC 的**扩展数据**（发生次数、里程等） |
| 0x0A | 列出所有支持的 DTC |

DTC 为 3 字节：前 2 字节是故障码编码（首字母 P/C/B/U + 数字，如 `01 01` → P0101），第 3 字节是故障类型；状态字节 8 个 bit（bit3=confirmed 已确认故障最关键）。

```
诊断仪: 03 19 02 08                 ← 列出状态含"已确认"(掩码0x08)的DTC
ECU:    07 59 02 FF 01 01 09 2F     ← 掩码支持FF；DTC 010109(P0101) 状态0x2F(已确认)

诊断仪: 03 19 01 08                 ← 查已确认DTC的数量
ECU:    05 59 01 FF 00 01           ← 共 1 个

诊断仪: 08 19 04 01 01 09 01        ← 读 P0101 的快照记录 1
ECU:    71 04 01 01 09 01 ...       ← 回快照数据（电压/转速/温度等，多帧）
```

---

### 4.12 0x14 清除故障码 ClearDiagnosticInformation

```
诊断仪: 03 14 FF FF FF              ← 清除所有 DTC
ECU:    01 54                       ← 清除成功
```

也可指定 DTC 组清除（如 `14 01 01 09` 只清 P0101）。

---

### 4.13 0x85 控制 DTC 设置 ControlDTCSetting

刷写过程中 ECU 大量报文异常，若继续记录会刷出一堆假故障。刷写前"关记录"、完成后"开记录"：

```
诊断仪: 02 85 01        ← 停止 DTC 记录
ECU:    01 C5

诊断仪: 02 85 02        ← 恢复 DTC 记录
ECU:    01 C5
```

---

### 4.14 0x34 / 0x36 / 0x37 下载三部曲（刷写核心）

**0x34 请求下载** —— 告诉 ECU 往哪写、写多大：

```
诊断仪: 0B 34 00 44 60 20 00 00 00 04 00 00
         │  │  │  └── 目标地址 0x60200000（4字节）
         │  │  └── ALFID=0x44：地址4字节、长度4字节
         │  └── 数据格式 0x00（不压缩不加密）
         └── 请求下载

ECU:    04 74 02 08 00              ← 每块最大 0x0800 字节（含SID+块号）
```

**0x36 传输数据** —— 循环发数据块，块号从 0x01 递增，超过 0xFF 回绕到 0x00：

```
诊断仪: 36 01 [0x7FE 字节数据]      ← 每块有效数据 ≤ 0x800-2，走ISO-TP多帧
ECU:    02 76 01                    ← 块1确认
诊断仪: 36 02 [数据]…  →  76 02
   ……循环直到写完 0x40000 字节……
```

**0x37 退出传输**：

```
诊断仪: 01 37
ECU:    02 77 [可选：CRC/签名]
```

0x35（RequestUpload）为反向"读出 Flash"，升级场景少用，格式与 0x34 对称。

## 5. 实战场景一：读 VIN（单帧请求 + 多帧响应）

VIN 共 17 字节，加上头部超过单帧 7 字节上限，必须走 ISO-TP 多帧：

```
诊断仪: 03 22 F1 90                       ← 单帧：读VIN
ECU:    10 14 62 F1 90 4C 56 56           ← 首帧：总长0x014=20字节，先发"LVV"
诊断仪: 30 00 0A                          ← 流控帧：块大小不限，帧间隔10ms
ECU:    21 41 42 33 4B 30 32 45           ← 连续帧1："AB3K02E"
ECU:    22 39 39 34 32 4E 30 30           ← 连续帧2："9942N00"
```

拼出 VIN：`62 F1 90` + `LVVAB3K02E9942N00`（17 字符 ✓）。

## 6. 实战场景二：ECU 程序刷写完整流程

标准刷写序列（顺序和前置条件是面试/实操高频考点）：

| 步骤 | 报文示例 | 作用 |
|---|---|---|
| 1 | `10 02` | 进编程会话（前置：车速=0 等，否则 7F 10 22） |
| 2 | `27 01` / `27 02 key` | 安全解锁 |
| 3 | `85 01` | 停止 DTC 记录 |
| 4 | `28 03 03` | 关闭应用通信报文 |
| 5 | `31 01 FF 00 …` | 擦除 Flash（回 78 挂起属正常） |
| 6 | `34 00 44 …` → `74 02 08 00` | 请求下载，获知块大小 |
| 7 | `36 01…NN` / `76 01…NN` | 循环传输数据块 |
| 8 | `37` | 退出传输 |
| 9 | `31 01 FF 01` | 完整性/签名校验 |
| 10 | `22 F1 95` 等 | 回读版本号确认刷写成功 |
| 11 | `28 00 03` + `85 02` | 恢复通信、恢复 DTC 记录 |
| 12 | `11 01` | ECU 硬复位，新程序生效 |

> 实际项目还会穿插功能寻址 `7DF` 预检查（确认全车 ECU 都可进编程会话）、网关路由配置等步骤。

## 7. 常见否定响应码（NRC）速查表

| NRC | 名称 | 典型场景 |
|---|---|---|
| 0x10 | 一般拒绝 | 其他 NRC 都不适用时 |
| 0x11 | 服务不支持 | ECU 根本没实现该服务 |
| 0x12 | 子功能不支持 | 服务有但该子功能没有 |
| 0x13 | 报文长度/格式错误 | 字节数不对、DID 缺失 |
| 0x21 | 忙，请重发 | ECU 负载高 |
| 0x22 | 条件不满足 | 车速≠0 时要求复位/IO控制 |
| 0x24 | 请求顺序错误 | 没要种子先发密钥、例程未启动先查结果 |
| 0x31 | 请求超出范围 | DID/RID 不存在 |
| 0x33 | 安全访问被拒绝 | 未进正确会话或未解锁就写数据 |
| 0x35 / 0x36 / 0x37 | 密钥错 / 次数超限 / 延迟未到 | 安全访问三连 |
| 0x70 | 不接受上传下载 | 刷写前置条件失败 |
| 0x71 | 传输中止 | 传输过程中出错 |
| 0x72 | 一般编程失败 | 例程/写操作执行失败 |
| 0x73 | 块序列计数器错误 | 36 块号不连续/重复 |
| **0x78** | 响应挂起 | 长操作中周期发送，重置 P2* 定时器 |
| 0x7E | 当前会话不支持子功能 | 默认会话发 2E |
| 0x7F | 当前会话不支持服务 | 默认会话发 34 |

## 8. ISO-TP（ISO 15765-2）传输层速查

UDS 报文在 CAN 上的"信封"，首字节高半字节为帧类型：

| 帧 | PCI 格式 | 用途 |
|---|---|---|
| 单帧 SF | `0X`（X=数据长度≤7） | 短报文，如 `03 22 F1 90` |
| 首帧 FF | `1X XX`（12位总长度） | 长报文开头，如 `10 14 …` |
| 连续帧 CF | `2X`（序号循环1~F） | 后续数据，如 `21 …` |
| 流控帧 FC | `30 BS STmin` | 接收方控制节奏，如 `30 00 0A` |

大于 4095 字节用Escape首帧（`1F XX XX XX`），刷写大块数据即走该模式。

## 9. AUTOSAR 中的服务归属

学习时建议"协议 ↔ 软件模块"双向对照：

| 服务 | AUTOSAR 模块 | 底层动作 |
|---|---|---|
| 10 / 11 | Dcm + EcuM | EcuM_RequestReset |
| 27 | Dcm（安全扩展） | 密钥算法在应用层回调 |
| 22 / 2E | Dcm + 应用层（RTE） | Dcm_ReadData / Dcm_WriteData 回调 |
| 2F | Dcm + IoHwAb | Dcm_ControlIo 回调 |
| 31 | Dcm + 应用层 | Dcm_StartRoutine 等回调 |
| 34 / 36 / 37 | Dcm + Mem/Fls | 走记忆栈写 Flash |
| **19 / 14** | **Dcm + Dem** | 故障数据真身在 Dem |
| 85 | Dcm + Dem | Dem 启停故障监控 |
| 3E / 28 / 87 | Dcm | 会话与通信管理 |

一句话：**Dcm 实现 ISO 14229 协议行为，Dem 管理 DTC 数据，应用层通过 RTE 回调提供"内容"。**
